Codex 全局规则与经验文件如何分工

核对日期：2026-11-05
分类：计算机与工具 → Codex

核心行为写在 AGENTS.md 中并保持独立可执行；经验背景可以放在 LESSONS.md，按需查阅。保存规则不等于证明助手会正确执行。

本篇学习重点

  • 建议掌握：核心规则独立可执行；文件存在、规则加载、实际执行是不同阶段。
  • 用时查阅：文件发现顺序、大小上限和具体位置。
  • 可以要求 Codex：请检查生效的规则来源，并用实际任务验证行为，不只展示文件。

两类文件的用途

文件 放什么
Codex 用户目录中的 AGENTS.md 跨项目通用的简短行为规则
study/AGENTS.md 本学习目录的记录、分类和维护约定
Codex 用户目录中的 LESSONS.md 失误原因、接口细节和验证案例

默认 Codex 用户目录是当前用户主目录下的 .codex，也可通过 CODEX_HOME 指定。全局发现时优先使用非空 AGENTS.override.md，否则使用 AGENTS.md；项目指令也有覆盖关系和大小限制。普通 LESSONS.md 没有专门的默认自动加载地位。官方加载说明

为什么不强制每次读经验文件

只要执行所需的信息已经完整写在 AGENTS.md，执行规则就不必依赖另一个文件。额外文件适合存放较长的细节。这是本次采用的维护设计，不是官方强制的分工。

例如核心规则可以直接要求：缺少聊天工具时检查 App Server，实际读取正文后才能声称读过。需要具体分页参数时，再查 LESSONS.md。

怎样判断规则有效

依次检查三件事：规则是否加载、是否理解正确、是否实际执行。一次成功不能保证以后永不复发，也没有数据支持具体的改善比例。

本次新聊天的验收截图显示，助手报告使用只读接口，并给出了符合原聊天的摘要。这是初步行为证据；截图未展示完整工具记录，不能独立证明全部执行过程。

本次纠正

全局经验最初被错误地到 study 下查找。后续核对发现全局 AGENTS.md 原本已包含核心动作，再次提出“把核心动作写进去”并非新增改进。最终调整是取消强制先读经验文件，并明确查阅位置。
